# AuditFlow

AuditFlow помогает составлять аудиторские чек-листы вручную или с ИИ, проводить проверки офлайн и выгружать результаты в Excel или PDF. По умолчанию интерфейс на русском. Казахский и английский доступны в меню аккаунта и на экране входа.

## Запуск демо

Установите Node.js 22.13 или новее. Демо использует вымышленные данные в браузере и запускается без аккаунта и Supabase.

```sh
npm ci
npm run build
npm start
```

Откройте [http://localhost:3000](http://localhost:3000). Для разработки используйте `npm run dev`. Для проверки офлайн-режима нужна рабочая сборка. На телефоне откройте её по HTTPS.

Публичное [демо на GitHub Pages](https://ryouta-dev.github.io/AuditFlow/) собирается из `main` командой `npm run build:pages`. Оно хранит проверки в браузере устройства и использует ИИ через совместимые API с поддержкой CORS. Для River используйте локальную серверную сборку.

## Облачные аккаунты и синхронизация

1. Создайте проект Supabase и примените SQL-файлы из [supabase/migrations](./supabase/migrations) по порядку.
2. Скопируйте `.env.example` в `.env.local`. Укажите `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` из проекта Supabase. Используйте publishable key или legacy anon key.
3. В Supabase откройте **Authentication → URL Configuration**. Укажите адрес приложения и разрешите перенаправления на `http://localhost:3000/dashboard` и `http://localhost:3000/recover` для локального запуска. Для развёрнутой версии добавьте эти же пути на её HTTPS-адресе. Проверьте доставку писем для подтверждения регистрации и сброса пароля.
4. После изменения переменных выполните `npm run build` и `npm start`. Зарегистрируйте два разных аккаунта для проверки доступа к данным.

На хостинге задайте переменные перед сборкой, выполняйте `npm run build` и обслуживайте Next.js по HTTPS. Файл `public/sw.js` и каталог `.next/static` должны быть из одной сборки.

Для существующего облачного проекта примените миграцию `202611200001_conformity_checklists.sql` перед обновлением приложения. Она добавляет серверную проверку результатов и пояснений для новых чек-листов.

## ИИ-помощник

Откройте **Чек-листы → Создать с помощью ИИ**. В демо введите адрес API и свой ключ, затем нажмите **Использовать ключ в этом сеансе**. Ключ хранится в памяти вкладки и исчезает после перезагрузки или кнопки **Удалить ключ из сеанса**.

| API | Адрес |
| --- | --- |
| OpenAI | `https://api.openai.com/v1/chat/completions` |
| OpenRouter | `https://openrouter.ai/api/v1/chat/completions` |
| Google Gemini, совместимый интерфейс | `https://generativelanguage.googleapis.com/v1beta/openai/chat/completions` |
| River | `https://api.river.ai/v1` |

Для River откройте AuditFlow на `http://localhost:3000`. Запрос отправится через локальный сервер, который обращается к фиксированному API River. По умолчанию используется `deepseek-ai/DeepSeek-V4.1-Flash`. Ключ вводится на время сеанса, как и для других провайдеров.

Для другого OpenAI-совместимого API укажите его HTTPS-адрес или локальный адрес `http://localhost` с нужным портом. API должен разрешать запросы из браузера (CORS). Если провайдер требует другое имя модели, укажите его в **Настройках модели**. Расходы на запросы учитывает провайдер.

Опишите задачу, вставьте исходный текст или загрузите до трёх файлов TXT, Markdown, DOCX, XLSX либо PDF с выделяемым текстом. Лимит каждого файла — 8 МБ, общего предпросмотра — 10 000 символов. Для PDF читаются первые 20 страниц. Для скана вставьте текст после распознавания. Из Excel извлекаются значения ячеек видимых листов. В API уходит отредактированный текст из формы после вашего подтверждения. Откройте предложение в редакторе, сверьте критерии с исходными материалами и сохраните чек-лист.

При входе в личный аккаунт через Supabase доступны встроенные настройки OpenAI, Google Gemini и OpenRouter. Этот режим отправляет запрос через аутентифицированный серверный шлюз.

В режиме помощника можно подготовить чек-лист, задать вопрос о проверке, предложить CAPA или создать черновик вывода для отчёта. Пошаговый анализ рассматривает ответы одной проверки и предлагает до трёх замечаний. Из сохранённого замечания можно отдельно открыть помощника CAPA.

Перед каждым запросом проверьте текст и подтвердите отправку. Поля аккаунта, местоположение и заметки аудитора не подставляются автоматически. Текст ответов и замечаний может содержать конфиденциальные сведения. Уберите их из предварительного текста. OpenRouter передаёт текст выбранному провайдеру модели.

Просмотрите предложение в редакторе и сохраните его обычной кнопкой. Вывод для отчёта можно отредактировать в предпросмотре и включить в PDF и Excel. Он хранится в памяти открытого сеанса. Офлайн доступны ручные функции аудита.

## Проверки

```sh
npm run lint
npm run typecheck
npm test
npm run test:db
npx playwright install chromium
npm run build
npm run test:e2e
```

Тесты шлюза подменяют ответы провайдеров и проверяют авторизацию, валидацию, ограничения и обработку ключей. Для браузерного теста сценария входа и подтверждения запроса соберите приложение с синтетическими параметрами. Следующие команды предназначены для отдельного сеанса PowerShell:

```powershell
$env:NEXT_PUBLIC_SUPABASE_URL='https://auditflow-fixture.supabase.co'
$env:NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY='synthetic-publishable-key'
$env:AUDITFLOW_E2E_AI='1'
npm run build
npm run test:e2e -- --grep 'requires consent'
Remove-Item Env:NEXT_PUBLIC_SUPABASE_URL,Env:NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY,Env:AUDITFLOW_E2E_AI
npm run build
```

Для живого вызова в демо нужен API-ключ провайдера. Для проверки реальных аккаунтов дополнительно подключите свой проект Supabase. При развёртывании облачного режима включите HTTPS и отключите запись тел запросов и ответов для `/api/ai` в прокси и средствах мониторинга. Ограничение частоты серверных вызовов действует в пределах процесса.
