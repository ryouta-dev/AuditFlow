# User guide

## Demonstration walkthrough

1. Open **Checklists → New checklist**. Give the checklist a name, define its scope, and group criteria by area or process. To begin with a draft from source materials, use **Generate with AI**, connect an API key, and review the extracted text before sending.
2. Write one observable condition per item. For example, *The emergency exit route is unobstructed*. Under **Verification and source**, add how to collect evidence and cite a document or clause when available. Review any criteria and references suggested by AI against the original source.
3. Select **Save checklist**, then **Start inspection**. Enter the inspected entity and date. The inspection uses a fixed copy of the checklist from the moment it started.
4. Mark **Conforms** or **Does not conform**. Use **Other outcome** when an item is outside the scope of this inspection or when evidence was unavailable. For a nonconformity, record the fact you observed, including where or what you sampled when relevant. For other outcomes, explain the reason.
5. Select **Complete inspection**. Resolve any missing decisions or notes. Use **View report** to see the individual decisions and outcome counts. Select **Download Excel** or **Print / Save PDF** to export them.

## Audit practice

Start with the objective, scope and criteria so the auditor knows which requirements apply. Use the checklist to guide observation, record review, interviews or sampling. When recording a nonconformity, identify the applicable requirement and the verifiable fact that demonstrates the gap. An unavailable record or an inaccessible area may limit what can be concluded. Mark that criterion **Not verified** and explain the limitation when you cannot establish an outcome. [ISO 19011:2026](https://www.iso.org/cms/live/live/en/sites/isoorg/contents/data/standard/08/89/88984.html?browse=tc) · [ISO/IAF Auditing Practices Group](https://committee.iso.org/home/tc176/iso-9001-auditing-practices-group.html) · [Tasmanian Government audit guide](https://nre.tas.gov.au/environment/climate-change/what-you-can-do/fact-sheets-and-resources/fact-sheet-conducting-an-audit)

New checklists report counts for the four outcomes. The scope and notes explain what was reviewed and where review was limited. Older checklists retain their response types, weights and scores.

## Findings and corrective actions

Select **Record finding** from the inspection details or open **More → Findings & CAPA** when a separate follow-up record is needed. Set the severity and record what you observed. Save, then add a corrective action with an owner, a due date, the root cause, and preventive work. For **Verified** and **Ineffective**, record the verification result.

## Work offline

Open the production app online once and check **Offline & sync** for **Available on this device**. Sign in and sync the records you need before going offline. While disconnected you can reopen the app, record answers, and view reports from records already on your device. Cloud accounts show **Completion pending** until the server accepts a local completion.

On reconnect, leave the app open while it syncs. If another device changed the same answer, open **Offline & sync** and compare both versions before selecting one. If the server has finalized the inspection, export pending changes before keeping the server version so you can review or re-enter the local notes later. Pending JSON exports contain inspection content. Store them securely. Browser storage removal can erase unsynced work.

## Navigation

Use the sidebar or Ctrl+K / Command+K to find checklists, inspections, and findings. The phone menu opens from the top left. Choose **English**, **Русский**, or **Қазақша** from the account menu, **Settings → Profile**, or the sign-in screen. The selected language applies to application screens, PDF reports, and Excel labels and is saved on this device.
